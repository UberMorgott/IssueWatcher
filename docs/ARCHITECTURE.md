# IssueWatcher — Architecture

Portable Windows desktop hub: track issues/comments across all my projects and platforms
(GitHub first; later CurseForge, Nexus Mods, Steam Workshop), reply from one place, and
dispatch local AI agents (Claude Code, Codex CLI) manually, in batches, or by auto rules.

## Decisions

| Area | Decision | Why |
|---|---|---|
| Shell | single Go exe: loopback HTTP server (`127.0.0.1`, OS-chosen free port; optional `IW_PORT` only if free) serving the embedded Vue app, opened in the default browser; no embedded webview | no WebView2 profile, no Wails beta; user runs many local servers, so never a fixed port |
| Loopback auth | per-run bearer token + port in `data\runtime.json`; browser always opened via one-time `/auth?t=` link → `HttpOnly SameSite=Strict` session cookie whose value is a persistent secret in `data\secrets\session.json` (owner-only DACL, `Max-Age` 400 days), so open tabs and the installed app window stay signed in across app and browser restarts (cookies are not port-bound); the bearer token still rotates every run; a damaged/missing secret is recreated (everyone signs in again); Host header must be `127.0.0.1`/`localhost` | other local processes/pages can't drive the API; DNS-rebinding guard |
| Single instance | named mutex `Local\IssueWatcher-<hash(data dir)>`; second launch reads `runtime.json`, `POST /api/open` → running instance opens the browser, exits | portable copies in different folders stay independent; mutex dies with the process (no stale lock) |
| Portable | all state in `data\` next to exe (config, SQLite, logs, worktrees). No registry/AppData — **one exception**: Settings → «Запускать вместе с Windows» writes `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\IssueWatcher` = `"<exe>" --minimized` (`internal/autostart`), only while on, deleted when off, rewritten at startup if the exe moved (`config.json general.startWithWindows` remembers the choice) | user requirement; autostart has no portable alternative |
| Start / focus | `--minimized` (or Settings → «Запускать свёрнутым», flag wins) = tray only, no browser tab. Tray click (double-click debounced 400 ms), «Открыть», notification click, second launch: `EnumWindows` finds the browser window whose title starts with the locale-independent marker `IssueWatcher · ` (the SPA's `document.title`), restores + `SetForegroundWindow`s it (foreground rights come from the click; second launch passes them via `AllowSetForegroundWindow`; `AttachThreadInput` fallback) and steers the tab with SSE `navigate`. Not found (background tab, other window) → a new tab opens and the old tabs get SSE `superseded` (+ `BroadcastChannel` from the new tab): dimmed overlay «Дашборд открыт в другой вкладке» with «Работать здесь», live updates and the title marker dropped. `IW_DEBUG=1` logs tray callbacks (hover/mouse-move callbacks never). Web app manifest lets the user install the dashboard as an app window, which makes the match reliable | browsers ignore `window.focus()` from a background tab |
| Notifications | the app's own popup cards (`internal/notify/popup_windows.go`), not Windows toasts/balloons: one borderless topmost `WS_EX_TOOLWINDOW` + `WS_EX_NOACTIVATE` layered window per card (no taskbar button, never takes focus), bottom-right of the primary monitor's work area (top-right with a top taskbar), per-monitor DPI v2. Card rendered in Go (`golang.org/x/image` + embedded Inter, SIL OFL, `internal/notify/fonts/OFL.txt`) into premultiplied RGBA → `UpdateLayeredWindow` (rounded corners, soft shadow, slide/fade). Kind icon (issue / comment / closed ✓), title, `repo#N`, 2-line snippet, time, ×. Stack ≤ 3: overflow folds into «+N ещё». Auto-hide (`Prefs.AutoHide`, default 8 s), hover pauses; click → `/item/:id` (group → `/issues?unread=1`) through the tray focus/new-tab logic. `Prefs` (types, muted repos, quiet hours, `RespectWindowsDnd` → `SHQueryUserNotificationState`) and `Theme` come from settings | Windows swallows balloons/toasts under Do Not Disturb / Focus assist and never reports clicks from the notification center; no AUMID/registry (portable); no webview |
| Tray | own Win32 tray: PNG icon rendered in Go with badge count (`99+`) (+ status dots later); menu Открыть / Тестовое уведомление / Выход; left-click opens browser; re-added on `TaskbarCreated` | quick status |
| DB | SQLite via `modernc.org/sqlite` (no cgo), embedded SQL migrations | reuse `E:\DEV\1сEPD\internal\store\sqlite.go` |
| GitHub API | GraphQL (explicit queries over `net/http`) for sync; REST (`go-github`) where simpler | rate limit 5000/h per token |
| GitHub auth | GitHub App created by **manifest flow** (browser: confirm create → install on all repos) → user token via web flow + PKCE + loopback `127.0.0.1:<port>`. Client secret stays in local `data\secrets\` (generated for this user, never shipped). Fallback: device flow. Details + sources: [GitHub auth](#github-auth) | "click Login → Accept, Accept → works", no shipped secret, no broker |
| Agents | local `claude -p` / `codex exec` child processes, Windows Job Object for cancel, streamed logs | user uses local subscriptions only |
| Publishing | dispatcher publishes (comments, labels, push, draft PR) via provider; agent only proposes | least privilege; merge always manual |
| AI control | same exe in MCP stdio mode (`modelcontextprotocol/go-sdk`) talking to running core over loopback+token | "tell Claude: reply to X" |
| Frontend | Vue 3 + Vite + TypeScript + Pinia + PrimeVue (DataTable) + ECharts; `//go:embed` bundle, history routing with server-side SPA fallback | table with filters/checkbox, charts |
| Language | UI Russian by default, English switch in Settings (`localStorage iw.lang`): `vue-i18n` (Composition API, Slavic plural rule), PrimeVue texts from `primelocale`, dates/relative time via `Intl`. Go-side text (tray menu, popup cards, auth pages) is Russian only | user request; no server round trip for a UI preference |

## Layout

```text

internal/domain         (later) Rule, Job, AgentProfile, Prompt; phase 1 records live in provider + store
internal/provider       Provider interface, capability flags, platform-neutral Project/Item/Comment
internal/provider/github  auth (manifest, web flow+PKCE, device, refresh), REST/GraphQL client, sync queries
internal/provider/github/githubtest  in-memory fake GitHub for tests (no network)
internal/syncer         poller: cursors, diff → events, unread badge, replies (named syncer: avoids clash with std sync)
internal/secret         owner-only JSON files (protected DACL = current user) for app keys + tokens
internal/config         data\config.json: typed sections, schemaVersion + migration, revision, validation, atomic write + .bak
internal/folders        repo ↔ local clone: git remote parsing, folder status, discovery under root folders
internal/runner         job queue, worktrees, claude/codex adapters (job objects), verify, review, publish (testdata/fakecli = fake CLI for tests)
internal/config         (+ agents.go: profiles, roles, prompt layers, per-project verify)
internal/store          SQLite + migrations
internal/api            loopback HTTP server: SPA, JSON API, auth (browser + MCP bridge)
internal/notify         Win32 tray icon, badge rendering, own popup notification cards (layered windows)
internal/autostart      HKCU Run entry for «start with Windows» (the only registry write)
internal/instance       single-instance mutex + data\runtime.json + data\port (last port)
internal/selfupdate     GitHub releases check, signed-manifest verification, exe swap/rollback, update hand-over
cmd/releasekey          Ed25519 release key (outside the repo) + signed manifest for release.ps1
internal/paths          portable data dir resolver (IW_DATA_DIR override)
frontend/               Vue app
data/                   runtime (gitignored): issuewatcher.db, runtime.json, config.json, logs\, secrets\
```

## Build & dev switches

- `pwsh -File build.ps1` → `build\bin\issuewatcher.exe` (npm build + `go build -H windowsgui`).
- Env: `IW_DATA_DIR` (data dir override), `IW_PORT` (preferred port, used only if free), `IW_NO_BROWSER=1` (log launch URLs instead of opening), `IW_HEADLESS=1` (automated runs: server + sync only — no tray icon, no popups, no browser, no window focusing, in-memory autostart instead of the registry), `IW_DEMO=1` (scripted badge + four popup cards + simulated click, for log-based verification), `IW_POPUP_SNAPSHOT=<dir>` (render sample popup PNG files — dark/light single, closed, stack — at 150 % and exit, no window).
- Fatal panics go to `data\logs\issuewatcher.log` (`debug.SetCrashOutput`); startup errors also show a MessageBox.

## Self-update and releases

- Releases: `pwsh -File release.ps1 -Version vX.Y.Z` on a clean `main` (no CI): frontend `npm ci` + build + eslint, `aegis verify -profile release` (else `go vet` + `go test -race`), `go build -trimpath -ldflags "-s -w -H windowsgui -X main.Version=…"`, `upx --best --lzma`, smoke test of the packed exe (`IW_HEADLESS=1`, scratch data dir, `/api/health` 200 with the version; the console copy `issuewatcher-cli.exe` appears and `status` exits 0 with the version, then is deleted: not an asset), then `issuewatcher-windows-amd64.exe` + `.sha256` + `manifest.json` {version, asset, size, sha256, minVersion?} + `manifest.json.sig` (Ed25519, key outside the repo, `cmd/releasekey`), tag and `gh release create` with notes from the commits since the last tag. `vX.Y.Z-pre` = GitHub prerelease = preview channel.
- Check: GitHub REST `releases/latest` (stable) or `releases` (preview: highest version incl. prereleases); `IW_UPDATE_BASE` overrides the API root for tests. Auto-check `updates.intervalHours` (default 24 h, ±10 % jitter, first ~1–2 min after start), never auto-install. A build whose version is not a tag (`dev`, `git describe` past a tag) checks but never installs.
- Install (`internal/selfupdate`): signed manifest (public key compiled in, `pubkey.go`) → version = tag, newer than running (no downgrade), ≥ `minVersion` → download to `.issuewatcher.exe.new` next to the exe, size + SHA-256 (+ GitHub asset digest) → swap: exe → `.issuewatcher.exe.old`, new → exe → start `exe --after-update=<pid>`.
- Hand-over: the new process writes `data\update-ready`, waits for the old PID to exit, takes the single-instance lock and **requires** the port in `data\port` (retries 5 s; taken by someone else → `ErrPortBusy`). Any start failure before the port is bound rolls back: exe → `.new`, `.old` → exe, `data\update-result.json` records why, the old exe starts with `--rolled-back=<pid>` and shows the error in Settings › Обновления. The old process, once ready is signalled, publishes `update.status` `restarting` and quits gracefully (tray/headless loop, HTTP + SSE, sync, SQLite; hard exit after 20 s); no ready within 30 s (or the child exits) → kill the child, roll back. The new process deletes `.old`/`.new` with bounded retries.
- Tabs: the session cookie survives restarts (`data\secrets\session.json`) and the port stays the same, so `EventSource` reconnects (0.5 s while restarting); on reconnect the page compares `/api/health` version and reloads on the same route/query. An after-update start never opens the browser; a normal (non-minimized) start waits up to 3 s (`api.StartGrace`, SSE retry capped at 2.5 s) for a tab of the previous run to reconnect and opens a new tab only if none does.
- API: `GET /api/update` (status), `POST /api/update/check`, `POST /api/update/install` (202; progress via SSE `update.status`). Tray menu «Проверить обновления» opens `/settings/updates` and checks.

## GitHub auth
Verified against GitHub docs 2026-09-28. Flow as built (`internal/api/github_auth.go`, `internal/provider/github/auth.go`):

1. Dashboard "Войти" → `POST /api/auth/github/start` (server opens the default browser itself). No app yet → local page `/auth/github/manifest?state=…` auto-POSTs form field `manifest` to `https://github.com/settings/apps/new?state=…`.
   Manifest: name `IssueWatcher-<8 hex>`, `public:false`, permissions issues/pull_requests/contents `write` + metadata `read`, `default_events: []`, webhook `active:false` (polling), `redirect_url` = `http://127.0.0.1:<port>/auth/github/app-created`, `setup_url` = `…/auth/github/setup`, `callback_urls` = [`http://127.0.0.1:<port>/auth/github/callback`, `http://127.0.0.1/auth/github/callback`].
2. User clicks **Create GitHub App** → GitHub redirects to `redirect_url?code&state` → `POST https://api.github.com/app-manifests/{code}/conversions` (no auth, 201; `id`, `slug`, `client_id`, `client_secret`, `webhook_secret`, `pem`; code valid 1 h) → stored in `data\secrets\github-app.json` with the registered port → redirect to `https://github.com/apps/<slug>/installations/new`.
3. User clicks **Install** (all repositories) → GitHub → `setup_url` → redirect to `https://github.com/login/oauth/authorize` with `client_id`, `redirect_uri` (current port), `state`, `code_challenge` (S256).
4. User clicks **Authorize** → `/auth/github/callback?code&state` → `POST https://github.com/login/oauth/access_token` (`client_id`, `client_secret`, `code`, `redirect_uri`, `code_verifier`) → `ghu_` token (8 h) + `ghr_` refresh token (6 months) → `data\secrets\github-token.json` → sync triggered, `auth.changed` published; if a dashboard tab is on `/api/events` it gets `navigate` (focus) and the GitHub tab shows "you can close this tab", else a fresh launch URL opens the dashboard.
   Later runs: "Войти" skips 1–3 and goes straight to 4 (one click, or none if GitHub remembers the grant).

- Refresh: `grant_type=refresh_token` 5 min before expiry, serialized (a used refresh token and its access token die). OAuth error on refresh, dead refresh token or API 401 → token deleted → signed out (app kept). Non-expiring tokens (user opted out) used as is.
- The three GitHub redirect paths skip the session-cookie check (cross-site navigations never carry the `SameSite=Strict` cookie); app-created/callback act only on our single-use in-memory `state` (TTL 1 h / 10 min); setup only starts a new authorize round trip. Host check still applies.
- Secrets: `data\secrets\` dir + files get a protected DACL granting only the current user; contents never logged. No secret in the binary, no broker.
- **Loopback port (open risk)**: the OAuth-apps doc says a loopback `redirect_uri` "does not need to match the port specified in the callback URL"; the GitHub-Apps callback doc is silent (only "up to 10 callback URLs", `redirect_uri` selects one). Not verifiable without a live app. Mitigations as built: (a) both exact-port and port-less `127.0.0.1` callbacks registered; (b) the registered port is remembered and preferred on later runs (like `IW_PORT`: only if free); (c) device flow fallback `POST /api/auth/github/device` (opens `verification_uri`, UI shows/copies `user_code`), which needs **Enable Device Flow** ticked once in the app settings (manifest has no field for it).
- Logout (`POST /api/auth/github/logout`) only forgets the local token; revoke at <https://github.com/settings/apps/authorizations> if needed.

## GitHub sync

- Repos: REST `GET /user/installations` → `GET /user/installations/{id}/repositories` (user token ∩ app installation). Repos no longer listed → `projects.active = 0` (hidden, data kept).
- Issues: GraphQL `repository.issues(first: 50, orderBy: UPDATED_AT ASC, filterBy: {since})` (issues connection has no PRs) with labels + comments (100/page, extra pages via `node(id)`). Cursor = max `updatedAt` per project (`projects.sync_cursor`); `since` is inclusive, upserts are idempotent.
- Tiered sync (`internal/syncer`, plan from Settings → Синхронизация, applied live): a **full reconcile** (list projects + GraphQL issues since each cursor) at start, on `POST /api/sync` / sign-in and every `reconcileMinutes` (balanced 60, fast 30); between reconciles every project gets a **change check** every `activeMinutes` (item changed within `activeDays`; balanced 5, fast 2) or `idleMinutes` (balanced 30, fast 15), ±10 % jitter, `concurrency` projects at a time, within an hourly request `hourlyBudget` (sliding window; checks beyond it wait).
- Change check (`provider.Poller`, GitHub `internal/provider/github/poll.go`): `GET /repos/{o}/{r}/issues?state=all&sort=updated&direction=asc&per_page=100&since=` and `…/issues/comments?…&since=` with `If-None-Match`. The ETag is kept per exact URL; `since` (high-water mark − 1 s overlap) only moves when something changed, so an idle repo repeats the URL and gets **304** (no body, free on the primary quota). On 200: pull requests are skipped, already-seen updates ignored, the changed numbers are fetched with one aliased GraphQL `issue(number:)` query per 20 and stored like a sync batch (events, unread, data.changed); a full page (100) means too many changes → that project is reconciled. Poll state (ETags, since marks, last check) lives in `projects.poll_state` / `checked_at` (migration 004). `X-Poll-Interval` raises a project's minimum interval. Providers without a Poller (CurseForge, Nexus, Steam later) get reconciles only; `provider.Scheduling` declares `PushSupported`, `PollMinInterval`, `RateBudget`.
- Rate limits: `x-ratelimit-*` tracked (limit/remaining/reset shown in Settings); 429, or 403 with `Retry-After` / "secondary rate limit" / remaining 0 → the whole schedule pauses until `Retry-After` / reset; secondary limits back off 1 → 15 min exponentially. `GET /api/sync` adds `mode, activeEvery, idleEvery, reconcileEvery, nextReconcile, lastCheck, projects, activeProjects, budget, budgetUsed, checks, notModified, rate{limit, remaining, reset}`.
- Rate limit: `x-ratelimit-remaining/reset` headers (REST + GraphQL); sync stops below 50 remaining until reset (replies may use the reserve); 403/429 with `Retry-After` or remaining 0 → rate-limited status.
- Diff → events (`store.ApplyItems`): new issue, new comment, issue open→closed. First sync of a project = silent baseline; own issues/comments never notify. Events mark the item `unread`.
- Popups: one card per event (click → `/item/<id>`); beyond 3 cards the oldest fold into «+N ещё» (click → `/issues?unread=1`). **Badge = number of unread items**; `POST /api/items/{id}/read` clears. Sync events are mirrored to open tabs as SSE (`cmd/issuewatcher/live.go`).

## HTTP API

JSON over the loopback server; session cookie or bearer required (except the GitHub redirect paths above). Legacy path aliases (`/api/repos`, `/api/issues…`, `POST /api/auth/{start,logout,device}`) are gone; only the `repo=` = `project=` query alias remains. Page/offset pagination is gone: lists load as keyset chunks (infinite scroll).

- `GET /api/auth/status` → `{providers:[{id, name, connected, login, avatarUrl, setupNeeded, state, error?}], …legacy GitHub fields (app, appSlug, installUrl, signedIn, login, device{pending,userCode,verificationUri,error})}`.
  `state`: `not_configured` (no GitHub App yet; first start creates it) · `disconnected` · `connecting` (browser round trip or device poll pending) · `connected` · `error` · `unavailable` (curseforge, nexus, steam: listed, not implemented).
- `POST /api/auth/{provider}/start` → `{step: create_app|authorize, url, opened: true}`; the server opens the default browser. Non-github: 501 (known) / 404.
- `POST /api/auth/{provider}/logout` → status; `POST /api/auth/github/device` → `{userCode, verificationUri, expiresIn, interval}` (server opens `verificationUri`; UI shows/copies `userCode`; completion → `auth.changed`).
- `GET /api/projects` → `[{id, name, url, platform, open, closed, unread, localPath, lastSync}]` (whole list: filters, badge); `?sort=name|open|closed|unread|lastSync&dir=asc|desc&q=&cursor=&limit=` → keyset chunk `{items, nextCursor, more, total}` (Projects page).
- `GET /api/items?source=&project=&state=open|closed|all&label=&q=&unread=1&cursor=|after=|ids=&limit=` → keyset chunk `{items:[{id, repoId, repo, number, title, url, author, state, rawStatus, labels, comments, unread, createdAt, updatedAt, closedAt}], headCursor, nextCursor, more, total?}`, order `updated_at DESC, id DESC` (index `items_updated_id`); `cursor` = next (older) chunk, `after` = rows newer than the head (live refresh; `more` = too many, start over), `ids` = re-check loaded rows against the filter (≤ 500); `total` (cheap count) on the first chunk and `after`; `limit` default 50, max 200; `source` = platform id, `q` = title/body substring or `#N`. Cursors are opaque (base64url JSON `[sortValue, id]`).
- `GET /api/items/{id}` → item + `body`; `GET /api/items/{id}/comments?cursor=&limit=` → `{items:[{id, author, body, url, createdAt, updatedAt}], nextCursor, more}` oldest first (`nextCursor` also finds comments added later); `POST /api/items/{id}/read` → 204 (badge refresh).
- `POST /api/items/{id}/comments {body}` → 201 comment; 400 empty, 404, 409 not signed in, 429 rate limited, 502 GitHub error.
- `GET /api/stats?project=&weeks=` → `{open, closed, weekly:[{start, opened, closed}], projects?}` (Monday-start UTC weeks, default 26; `projects` = per-project totals when `project` omitted).
- `GET /api/sync` → `{running, signedIn, lastSync, lastError, rateLimitedUntil, interval}`; `POST /api/sync` → 202.
- `GET /api/settings` → `{revision, settings, info}`: `settings` = the whole `config.json` document (sections `general` (language, startWithWindows, startMinimized), `appearance`, `notifications` (enabled, per-kind switches, mutedProjects, quiet hours, group, autoHideSeconds, respectDnd), `sync` (mode balanced/fast/custom, activeDays, per-provider plans), `projects` (roots, exclude, scanDepth)); `info` = data dir, config path, version, exe, sync presets. `general.startWithWindows` shows the Run value (the truth).
- `PATCH /api/settings {revision, patch}`: `patch` is a JSON merge patch (RFC 7396) of `settings`. 409 `{error, current}` when `revision` is stale (another tab saved first; the SPA re-applies once on top of `current`), 400 `{field, code, params, error}` when validation fails (codes: json, enum, range, time, differ, absPath, tooMany, section; the SPA localises them). On success: side effects first (Run entry), then atomic write (temp + fsync + rename, previous file → `config.json.bak`), live apply (popup prefs/theme, toast filter, sync plan) and SSE `settings.changed` (the new doc) to every tab. `POST /api/settings/reset {revision, section}` restores one section's defaults; `GET /api/settings/export` downloads the settings. Secrets and the runtime token never live in `config.json`.
- Appearance (`settings.appearance`): `mode` dark/light/system, `paletteId` (presets in `info.palettes`: four base colours accent/background/surface/text per mode), `custom.{dark,light}` overrides (empty = palette), `fontFamily`, `fontScale` 0.85–1.30, `density`. The server rejects bad hex and any combination whose text contrast on surface or background is below WCAG AA 4.5:1 (code `contrast`). The SPA (`lib/appearance.ts`) derives every `--iw-*` token from the four colours, updates PrimeVue via `updatePreset` (`palette(accent)`, surface scale, datatable padding), re-themes ECharts and caches the result in `localStorage iw.paint` for the first paint; popups use the same colours (`cmd/issuewatcher popupTheme`).
- `config.json` v2 (`schemaVersion: 2`): v1's flat `startWithWindows`/`startMinimized` move to `general`; v1 `pollIntervalMinutes` N ≠ 5 becomes sync mode `custom` with GitHub `activeMinutes = N` (5 = the balanced default). Unknown keys (nested too) survive every write.
- `GET /api/folders` → `[{projectId, name, url, platform, localPath, status}]`, status `none|ok|missing|notGit|mismatch` (`ok` = a git clone whose remote is the project; linked worktrees resolved via the `.git` file + `commondir`); `PUT /api/projects/{id}/path {path}` (absolute, empty unmaps) → row; `POST /api/folders/discover` scans `settings.projects.roots` (depth `scanDepth`, skipping `exclude` names, hidden folders and clone interiors, ≤ 20000 folders, 30 s) → `{suggestions:[{projectId, name, path, remote}], visited, roots}`; nothing is mapped until the user accepts.
- `POST /api/notifications/test` → 204, shows a sample popup.
- Agent jobs (`internal/api/jobs.go`, Runner above): `GET /api/jobs?state=<state>|active&flow=&project=&item=&cursor=&limit=` → `{items: Job[], nextCursor, more, total?}` newest first; `POST /api/jobs {itemIds[], flow: fix|reply, profileId?}` → 201 `{jobs:[{itemId, job?, error?: exists|not_found}]}` (profile default = role coder/responder; 400 bad flow/profile/empty); `GET /api/jobs/{id}`; `GET /api/jobs/{id}/log?attempt=` → `{attempt, steps:[{t, kind: info|text|tool|output|error|stderr|result, text}]}`; `GET /api/jobs/{id}/diff?attempt=` → text/plain; `POST /api/jobs/{id}/cancel|retry|dismiss|pr|push` → Job (`push`: direct fix commits → the platform) (409 wrong state / publishing unavailable / signed out, 502 publish failed → job back in needs_review with `result.publishError`); `POST /api/jobs/{id}/reply {body}` → Job (done). `GET /api/agents/detect` → `[{cli, path, version}]` (CLIs on PATH, native codex.exe). Job = `{id, itemId, projectId, flow, state, profileId, attempt, phase, branch, worktree, baseSha, error, result, createdAt, startedAt, finishedAt, updatedAt, repo, number, title, itemUrl, localPath}`. Item rows carry `job: {id, flow, state, startedAt, outcome}` (newest job).
- Settings `agents` (config v3): `{maxParallel, profiles:[{id, name, cli: claude|codex, path, model, args[], timeoutMinutes, maxParallel, maxBudgetUsd}], roles:{coder, responder, verifier}, prompts:{system, fix, fixDirect, reply, review}, projects:{"owner/repo": {mode: direct|worktree-pr, prompt, verify, noAegis, jobMcp?}}, jobMcp}` (config v4; `jobMcp` default true, project value nil = inherit); prompts equal to the built-in text are stored as `""` (a newer build's defaults apply; `""` = reset). Validation codes add `id, duplicate, required, profile, tooLong`.

## Domain

- `Source` — connected account on a platform (github:UberMorgott). Tokens stored in `data\`.
- `Project` — platform object (repo / mod page) + optional local folder mapping. Auto-discovery scans configured roots for git remotes.
- `Item` — issue or equivalent, key `(source, external_id)`; unified status + raw platform status.
- `Thread` / `Comment` — discussions with platform IDs; replies go through provider.
- `Rule` — match (project, event new_issue/new_comment, any label) → flow (`fix`, `reply`, `label`) + agent profile + daily cap; queues a job, never publishes (except labels when `autoApplyLabels` is on).
- `Job` — one per item per flow; states queued/running/needs_review/done/failed/cancelled; attempts, logs, result.
- `AgentProfile` — CLI (`claude`/`codex`), model, role (coder/responder/verifier), flags, limits.
- `Prompt` — global layer + per-project layer + per-flow template.

## Runner

`internal/runner` (Phase 2, design reviewed with Codex 2026-09-28). Manual only: nothing runs or publishes without a click.

- **Run mode** per project (`agents.projects["owner/repo"].mode`, config v4; Settings › Проекты и папки): **`direct` (default)** or `worktree-pr` (the Phase 2 flow below, kept as an option). Owner decision 2026-09-28: the agent should work exactly like his own sessions — his global `~/.claude` CLAUDE.md, the project's CLAUDE.md/AGENTS.md, project `.claude` settings, MCP servers (Aegis…) — plus our task prompt; one folder, no worktrees or private clones, simplest thing that works. The v3 → v4 migration writes `mode: direct` into every existing project entry.
- **Direct fix flow**: cwd = the mapped folder (`folders.Check == ok`), on whatever branch is checked out. No isolation flags (no `--setting-sources`, `--safe-mode`, `--bare`): the user's setting sources stay on. Claude gets our whole prompt (system layer + project notes + `prompts.fixDirect` with the issue wrapped as untrusted data) via `--append-system-prompt-file` and a one-line user turn; codex gets it as its input in `-C <folder>` with the user's config. The prompt says: follow the project's rules, verify, commit only your own files with a message containing `Fixes #N`, never push; structured result `{status: fixed|not_reproduced|needs_info|failed, summary, commits[], verify, notes}` (claims only). Uncommitted changes are allowed (owner's choice): `git status --porcelain` before/after goes into `result.local.dirtyBefore/After`, the list is added to the prompt ("leave these alone") and the UI warns. One job per folder (on top of one per project and the global/profile limits). **Facts after exit** (phase `check`, also after a failure/cancel): new commits `start..HEAD` (sha, subject, `Fixes #N` by GitHub's closing keywords), working tree, branch, `git fetch origin` + `git branch -r --contains <head>`; diff `start..HEAD` → the job diff (the index is never touched). `result.local.outcome`: `fixed_local` («Исправлено локально — ждёт push») · `pushed` · `closed` · `not_reproduced` · `needs_info` · `no_commit` · `failed` (agent said so → job failed). Only an explicit project `verify` command runs afterwards (the agent verifies by the project's rules); the optional verifier reviews the commits read-only. State: `needs_review` → **«Push»** (`POST /api/jobs/{id}/push`, manual only: `git push <project push URL> <head>:refs/heads/<branch>` in the folder (never `origin`: it may point elsewhere now, and the token must only reach the platform) with the app token via `GIT_CONFIG_*` env, the user's own pre-push hooks run) → `done`; when sync sees the issue closed (the pushed `Fixes #N`), the runner marks the job `done` / `outcome: closed` (also a pushed one); a commit that is still only local (the issue was closed another way; checked against the local remote-tracking refs) keeps the job `needs_review` with `local.closed`, so it can still be pushed or dismissed. «Отклонить» never touches the folder. Reply jobs are unchanged (read-only in the folder, draft, «Отправить»).

- **Jobs** (`jobs` table, migration 005): one per item and flow (`fix` | `reply`); a partial unique index allows one unfinished (`queued|running|needs_review`) job per item+flow, so a batch skips items that already have one (`error: "exists"`). States: `queued → running → needs_review → done` (fix: draft PR opened; reply: comment posted); `failed` (agent/git error, timeout, restart); `cancelled` (Отменить, or Отклонить from needs_review/failed). `phase` while running: prepare, agent, verify, review, publish. **Retry** = next `attempt` of the same job from a clean worktree; logs/diffs stay per attempt; done jobs cannot be retried. **Restart**: jobs left `running` become `failed` with `errorCode: interrupted` (never auto-rerun: the agent may have been half way); queued jobs run. `result` JSON = `runner.Result` {errorCode, agent, diff, verify, review, draft, pr, comment, publishError, cleanupError, baseBranch}.
- **Scheduling**: oldest queued first; one running job per project, `profile.maxParallel`, `agents.maxParallel` overall (default 2). Every state change → SSE `job.changed`; log steps → `job.log` batched every 250 ms (a chatty agent cannot overflow a tab's SSE buffer).
- **Fix flow (worktree-pr mode)**: needs a mapped folder whose remote is the project (`folders.Check == ok`), else `failed` / `errorCode: no_folder` (UI links Settings › Проекты и папки). Default branch from the provider (GitHub `GET /repos/{o}/{r}`), else `origin/HEAD`, else main/master; `git fetch origin <branch>` (offline → last fetched state); `git worktree add --no-track -b iw/<number>-<slug> data\worktrees\<repo>\<job> <sha>` (taken name → `-j<job>`; `core.longpaths=true`). The user's working copy is not touched (the worktree shares its object store, refs and config — see open decisions). After the agent: `git add -A` in the worktree + `git diff --cached -M <base>` → diff summary (files, +/−, commits the agent made) and `data\jobs\<id>\<attempt>.diff` (≤ 5 MB). Verify: `aegis verify -root <worktree>` when the mapped folder has `.aegis` and `aegis` is on PATH (unless `noAegis`), else the project's `verify` command via `cmd.exe /d /s /c`, 30 min, output tail 12 KB; a failed verify still ends in `needs_review` with a red badge. Optional **verifier** role: a read-only second agent reviews the diff (`result.review`). An empty diff also ends in `needs_review` (the agent says why); «Создать PR» refuses it.
- **Reply flow**: the responder runs read-only in the mapped folder (or an empty scratch folder) and returns `{reply, notes}` → `result.draft`; the UI edits it, «Отправить» posts via `syncer.Reply` (provider) → `done` with the comment.
- **CLI contracts** (verified on claude 2.1.284, codex-cli 0.157.1): prompt on stdin. Claude: `claude -p --output-format stream-json --verbose --no-session-persistence --permission-prompts none --append-system-prompt-file <f> --json-schema <schema>` + fix `--permission-mode auto --disallowedTools "Bash(git push:*)" "Bash(gh:*)" …` / read-only `--permission-mode dontAsk --tools Read,Grep,Glob`, `--model`, `--max-budget-usd` (profile budget), profile args. `result.structured_output` carries the schema object. Codex: native `codex.exe` resolved behind the npm `codex.cmd` shim; `codex exec --json --ephemeral -C <dir> -o <last.txt> --output-schema <schema.json> -s workspace-write|danger-full-access|read-only [--skip-git-repo-check] [-m model] … -` (system text prepended to stdin); direct fix = `danger-full-access` (workspace-write keeps `.git` read-only and, on Windows, runs as a sandbox user git rejects as "dubious ownership", so the `Fixes #N` commit fails; E2E 2026-09-29), worktree fix = `workspace-write`, read-only flows = `read-only`. Events → steps: claude `system/init`, assistant text/tool_use, user tool_result, `result` (cost, turns, is_error); codex `thread.started`, `item.started/completed` (agent_message, command_execution, file_change, mcp/web), `turn.completed` (tokens), `turn.failed`. Structured results are the agent's claim; the dispatcher trusts only the diff and verify.
- **Job MCP server** (`agents.jobMcp`, default on; per-project `agents.projects[..].jobMcp`, unset = inherit; owner decision 2026-09-29): IssueWatcher's MCP server is attached only to a job's own agent runs, never registered in the CLIs' global/project config, so the owner's other sessions in that folder see nothing. Server = the app's own exe (`os.Executable`) `mcp --item <itemId>`, env `IW_DATA_DIR` = the app's data dir (the agent env drops `IW_*`); scoped tools `get_item`, `list_item_comments` (read-only, item fixed, no id argument; no write/publish tools: the app publishes after review). Claude: `--mcp-config data\jobs\<id>\<flow>.mcp.json` (`{mcpServers:{issuewatcher:{type:stdio,command,args,env}}}`, removed after the run) + `--allowedTools mcp__issuewatcher`; no `--strict-mcp-config`, the owner's MCPs still load. Codex: `-c mcp_servers.issuewatcher={command=..,args=[..],env={IW_DATA_DIR=..},default_tools_approval_mode="approve"}` (exec never asks, so read-only tools are pre-approved). A note about the tools is appended to the system text of that run.
- **Processes** (no zombies): every CLI and verify command starts **suspended**, is assigned to a kill-on-close **Windows Job Object** and only then resumed (`proc_windows.go`), so nothing it spawns (node children, MCP servers such as aegis/serena, shells, test runners) escapes. Output comes through pipes the runner owns, so a straggler holding stdout cannot keep a run alive. On a normal exit, cancel, timeout and app shutdown the whole tree is terminated and the runner waits until the job object reports no live process (a survivor is logged as an error). While a tree runs, its pids + creation times are written to `data\jobs\<id>\procs.json` every 2 s (removed when it ends); the next start kills recorded processes that still match pid **and** creation time, plus their younger descendants (reused pids are left alone). Timeout = `profile.timeoutMinutes`. Env scrubbed: `GH_TOKEN`, `GITHUB_TOKEN`, `GIT_ASKPASS`, `GIT_CONFIG_*`, `IW_*`, surrounding-agent markers (`CLAUDECODE`, …).
- **Prompts**: system (global) + per-project notes + flow template (fix / reply / review), variables `{repo} {issue.number} {issue.title} {issue.url} {issue.body} {comments} {localPath} {branch} {diff} {labels}` (label: the repo's labels, one `- name — description` per line). Issue body, comments and diff are wrapped in `<untrusted-issue-content source="…">` blocks (tags inside the text are defanged); the title is one line without tags; the system prompt says these are data, not instructions, and forbids push/PR/comments; the worktree fix template also forbids commits, the direct one (`fixDirect`) asks for a `Fixes #N` commit. Bodies ≤ 60 KB, newest comments ≤ 60 KB, diff ≤ 100 KB. Delimiters are not a sandbox: the agent runs with the user's rights (see open decisions).
- **Publishing** («Создать PR», fix + needs_review, synchronous): lock (`running/publish`), `git add -A` + commit if anything is uncommitted (`fix: <title> (#N)` + summary; repo identity, else `<login>@users.noreply.github.com`), `git push --no-verify <project URL>.git +HEAD:refs/heads/iw/…` with the user token passed as `GIT_CONFIG_*` env `http.<push URL>.extraHeader` (never argv; scoped to that URL, so a `url.*.insteadOf` rewrite in the clone never carries it to another host) and credential helpers off, reuse a PR found by `head`, else `POST /repos/{o}/{r}/pulls {draft: true, body: "Fixes #N" + summary + verify}`; then `done`, worktree + local branch removed. Failure → back to `needs_review` with `publishError`. «Отклонить» / cancel remove the worktree and branch.
- **Tray / UI**: `OnFinished` shows «Агент закончил: repo#N — исправлено локально / не воспроизводится / нужна информация / ошибка» cards (summary below; notifications on, not quiet hours/DND); click → the issue (`/item/<id>`). The SPA shows the same as a toast. A running job shows a spinner, elapsed time and the latest step (from `job.log`) on Issues rows, the item page and Jobs; the log is collapsed. Issue badges carry `{id, flow, state, startedAt, outcome}`.

## Automation (Phase 3, planned)

Plan drafted by Codex 2026-09-29, checked against the code and cut to the minimum; checklist in `TASKS.md` → Phase 3. Rules are off by default; publishing (comment, push/PR) stays a click; labels too unless `autoApplyLabels` is on.

**Owner decisions (2026-09-29)**: every automation behaviour is a setting — a global default in `agents.automation` plus an optional per-project override in `agents.projects["owner/repo"].automation` (unset field = inherit). (a) Rules may queue `fix` only where `allowAutoFix` is on (default off). (b) No separate `verify` flow: the fix agent triages the issue itself (`not_reproduced` / `needs_info`). (c) Rule-made label suggestions are applied without a click only where `autoApplyLabels` is on (default off = suggest, «Добавить метки»). Attempt limits (`maxAttempts`) follow the same global + per-project pattern. Daily caps (owner, 2026-09-29, revised): the global `maxPerDay` is one **total** over all projects; a project `maxPerDay` is an extra per-project cap (unset = none), not an override of the total.

- **Flows**: `label` = read-only agent picks from the repo's existing labels (list passed in the prompt; names outside it dropped after parsing) → `result.labels` → `needs_review`; «Добавить метки» (`POST /api/jobs/{id}/labels {labels[]}`) re-checks names against the repo list, **adds only** (never removes), updates the local item labels → `done`; a rule job where `autoApplyLabels` is on does that step itself (still additive only). Default profile: label → `roles.responder`. Prompt: `prompts.label` (same layers and untrusted-content wrapping).
- **GitHub adapter**: `ListLabels(project)` + `AddLabels(item, names)` (`issues: write` is already in the App manifest, `internal/provider/github/auth.go`); `Capabilities.SetLabels = true`; `GET /api/projects/{id}/labels`.
- **Jobs table** (schema step 006): fresh DB, no migration — owner decision 2026-09-29: the `jobs` table is recreated empty with the new schema (old job rows discarded; sources, projects, items, folder mappings kept): `flow IN (fix, reply, label)`, new `origin` (`manual|rule`, default manual) and `rule_id`; indexes `jobs_item`, `jobs_state`, `jobs_active`. `id` is AUTOINCREMENT seeded with the old maximum, so `data\jobs\<id>` files of discarded jobs are never picked up by new ones. Job JSON adds `origin, ruleId`; `GET /api/jobs?origin=`.
- **Attempt history** (closes open decision 4): Retry snapshots the finished attempt `{attempt, state, error, errorCode, result, startedAt, finishedAt}` to `data\jobs\<id>\<attempt>.json` next to its log/diff (no new table); `GET /api/jobs/{id}/attempts` → earlier snapshots + the current attempt.
- **Config v5**: `agents.prompts.label`; `agents.automation {enabled: false, maxPerDay: 10, maxAttempts: 2, allowAutoFix: false, autoApplyLabels: false, rules: []}`, rule `{id, enabled, project: "owner/repo", event: new_issue|new_comment, labelsAny[], flow: fix|reply|label, profileId, maxPerDay (0 = only the total/project caps)}`; per-project override `agents.projects["owner/repo"].automation {enabled?, maxPerDay?, maxAttempts?, allowAutoFix?, autoApplyLabels?}` (absent = inherit; `maxPerDay` absent = no project cap; `Agents.AutomationFor(project)` resolves → `TotalPerDay` + `ProjectPerDay`). Default total `maxPerDay: 10`: every rule job is a full Claude/Codex agent run on the owner's subscription quota, so a conservative total across all projects (a few runs per 5 h window) keeps automation from draining the quota needed for manual work. v4 → v5 only adds defaults (unknown keys kept).
- **Rules** (runner, called from the syncer `OnUpdate` callback in `cmd/issuewatcher/main.go`, after `store.ApplyItems` committed): input = the sync events, which already exclude the silent first-sync baseline and the user's own issues/comments (`store.applyItem`). First enabled rule matching project + event + any label wins. Checks (with the project's effective settings): automation on, profile exists, `fix` needs `allowAutoFix` and `folders.Check == ok`, no unfinished job for item+flow (`jobs_active`), rule jobs for item+flow < `maxAttempts`, rule jobs in the last 24 h under the total / project / rule caps — counted and inserted in **one SQLite transaction** (`store.Automate`; one connection + a runner mutex serialise batches). **Caps (implemented, step 6)**: (1) the global `maxPerDay` caps rule jobs of **all projects together** in a rolling 24 h window (`created_at > now − 24 h`) → `total_cap`. (2) A project `maxPerDay` (unset = none) caps that project's rule jobs in the same window, on top of (1) → `day_cap`. (3) A rule's `maxPerDay` (0 = none) caps that rule's jobs in the same window, on top of (1)–(2) → `rule_cap`. (4) `maxAttempts` (effective) caps rule jobs ever made for item + flow (cancelled/dismissed ones count; manual jobs never count and are never blocked). Manual jobs do not count toward any cap. Over a cap → skipped, never deferred. No automatic retries. Only events that match a rule are logged (automation off for the project or no matching rule → nothing); one decision per item + flow per batch. Skip reasons: `no_profile`, `unavailable` (label rule without a label provider), `auto_fix_off`, `no_folder`, `exists`, `max_attempts`, `total_cap`, `day_cap`, `rule_cap`. Each decision goes to `automation_log` (migration 007: at, item_id, event, rule_id, flow, decision, reason, job_id; newest 5000 kept); `GET /api/automation/log?cursor=&limit=` → `{items:[{id, at, itemId, event, ruleId, flow, decision, reason, jobId, repo, number, title}], nextCursor, more}` newest first. Events are processed in memory: a crash between the sync commit and the callback loses that cycle's triggers (no pending-event replay).

## Control (Phase 4)

Checklist: `TASKS.md` → Phase 4. `cmd/issuewatcher` subcommands run **before** the single-instance lock: no tray, DB, provider or sign-in of their own; they talk to the running app only through `internal/control`, a client of the HTTP API above.

- **Client** (`internal/control`): reads `data\runtime.json` on every call (a restarted app has a new port + token), accepts only `http://127.0.0.1:<port>`, sends the bearer token, never follows redirects; deadline 10 s for reads, 6 min for POSTs (a push runs the user's hooks under the runner's 5 min git timeout); a POST that gets no answer fails as "outcome unknown: check the item/job before retrying", never a plain retryable error; the API's `{error}` body becomes the message. App not running → error, it never starts the desktop process.
- **CLI**: `status`, `projects`, `items`, `item <id>`, `jobs`, `job <id>`, `job log <id>`, `sync`, `reply <itemId>`, `jobs create --flow fix|reply|label <ids>`, `job cancel|retry|dismiss|push|pr <id>`, `job reply <id>`, `job labels <id> <names>`; bodies from `--body-file` or stdin; JSON on stdout; exit 0 ok / 1 API error / 2 usage / 3 not running. The release exe is `-H windowsgui`: attach to the parent console (`AttachConsole(ATTACH_PARENT_PROCESS)`) when stdout is not a pipe or file. Verified on the UPX release build (2026-09-29): with pipes (MCP clients, agents' shells, `| Out-String`) stdio and exit codes work; an interactive shell does not wait for a GUI-subsystem exe (output arrives after the prompt, exit code lost), so the app keeps a console copy for shells: on every start (past the update rollback point) it writes `issuewatcher-cli.exe` next to itself = its own bytes with the PE optional-header `Subsystem` switched 2 (GUI) → 3 (console), only when it is a windowed build and the copy differs (a running copy is renamed to `.issuewatcher-cli.exe.old`, removed on a later start). Same program, same version: no second build, release asset or manifest entry, so old clients (which fetch only `issuewatcher-windows-amd64.exe`) and every self-update get a matching copy on the next start; the CLI needs the running app anyway. Shells wait for it, output precedes the prompt, `$LASTEXITCODE`/`%ERRORLEVEL%` are right (verified on the UPX build 2026-09-29). Started without a subcommand, the copy prints the usage and exits 2 (the desktop app is `issuewatcher.exe`). No proxy launcher (Codex's suggestion): the exe runs the CLI in-process already, so a console child of the same bytes needs no stdio relay or job object. MCP clients keep calling `issuewatcher.exe mcp` (pipes; a console exe spawned by a GUI client would open a console window). Any first argument that is a word (not `-flag`/`/flag`) is a subcommand, dispatched in `main()` before `run()`: no log file, lock, tray or message box.
- **MCP**: `issuewatcher mcp [--item ID]` (`--item` = a job's scoped server, Runner → Job MCP server), stdio transport of `github.com/modelcontextprotocol/go-sdk` (v1.8.0). Domain tools only (no raw HTTP tool): `list_projects, list_items, get_item, list_item_comments, list_jobs, get_job, get_job_log, sync_now, reply_item, start_jobs, cancel_job, retry_job, send_job_reply, apply_job_labels, push_job, create_pr`; local item/job ids, pages ≤ 50 (`get_item` = first comments, `list_item_comments` pages on from its `nextCursor`; `get_job_log` = last `tail` ≤ 200 steps). Results are the API's JSON as one text content; API errors become `isError` results with the API message. The server starts even when the app is not running (tools then answer "not running"). stdout carries only JSON-RPC; logs go to `data\logs\mcp.log` (warn+). Publishing tools rely on the MCP client's approval (owner decision 2026-09-29). Never registered globally: manual use = one session's `claude --mcp-config <file>`. Every action goes through the same endpoint and state checks as the UI.
